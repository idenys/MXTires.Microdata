# MXTires.Microdata release notes
##Release v. 1.0.5.1
<i>WebPage.Specialty</i> is now typed <i>MedicalSpecialty</i>. schema.org's <i>specialty</i> takes a <i>Specialty</i>, whose values are the <i>MedicalSpecialty</i> members; the library's own <i>Specialty</i> enum was empty, so the property could never hold a valid value, and that enum is removed. <i>CreditCard.NoCredit</i> no longer carries the invented <i>https://schema.1010tires.com/NoCredit</i> URI, which no vocabulary defines; it is marked <i>[Obsolete]</i> and throws when serialized, like <i>PaymentMethod.VisaCheckout</i>. Leave the property unset instead. The enum URI test now requires every URI to be a schema.org (https) or GoodRelations URI.

##Release v. 1.0.5.0
<b>Breaking changes</b> - JSON-LD output fixes from issue #42.
<ul>
<li><b>Enumerations.</b> One library-wide <i>SchemaEnumConverter</i> (registered in <i>Thing</i>'s serializer settings, replacing the per-property <i>StringEnumConverter</i> attributes) writes each member's <i>[EnumMember]</i> URI. A <i>[Flags]</i> combination is written as a JSON array instead of one comma-joined string. A member with no URI, or an undefined value, throws <i>JsonSerializationException</i> instead of writing a bare name or a number. Callers that serialize with their own <i>JsonSerializerSettings</i> can add <i>new SchemaEnumConverter()</i> to get the same output.</li>
<li><b>Nullable properties.</b> Every enum-typed property (except <i>WarrantyPromise.WarrantyScope</i>, which its constructor always sets) is now nullable, so an unset property is no longer written as <i>0</i> or as its first member (e.g. <i>Offer.ItemCondition</i> no longer claims <i>NewCondition</i>). The same applies to <i>MonetaryAmount.MinValue</i>/<i>MaxValue</i>, <i>QuantitativeValue.Value</i>, <i>PriceSpecification.ValueAddedTaxIncluded</i>, <i>TypeAndQuantityNode.AmountOfThisGood</i>, <i>Event.RemainingAttendeeCapacity</i>, <i>BroadcastEvent.IsLiveBroadcast</i>, <i>PublicationEvent.Free</i>, <i>LocalBusiness.HasDriveThroughService</i>, <i>Message.DateRead</i>/<i>DateReceived</i>/<i>DateSent</i>, <i>LiveBlogPosting.CoverageStartTime</i>/<i>CoverageEndTime</i>, <i>AggregateOffer.OfferCount</i>, <i>ListItem.Position</i>, <i>ItemList.NumberOfItems</i> (which also no longer throws when <i>ItemListElement</i> is null), and <i>PropertyValueSpecification.MultipleValues</i>/<i>ReadonlyValue</i>/<i>ValueRequired</i>. <i>Offer.BusinessFunction</i> no longer defaults to <i>Sell</i>, and <i>Rating.BestRating</i>/<i>WorstRating</i> no longer default to 5 and 1; schema.org assumes those values when the properties are omitted.</li>
<li><b>URIs.</b> Added schema.org URIs to the 22 enumerations that had none, plus <i>ActionStatusType</i>, <i>RsvpResponseType</i> and <i>DigitalDocumentPermissionType</i> (which used bare names), <i>MerchantReturnEnumeration</i> (bare names) and <i>DeliveryMethod.OnSitePickup</i>/<i>LockerDelivery</i>. schema.org URIs now use https: <i>ItemAvailability</i>, <i>GameServerStatus</i>, <i>GamePlayMode</i>, <i>PaymentMethod.CreditCard</i> and the default <i>Thing.Context</i> (<i>https://schema.org</i>). GoodRelations URIs are unchanged.</li>
<li><b>Enum bugs.</b> All three <i>ReturnMethodEnumeration</i> members wrote <i>ReturnInStore</i>; each now writes its own URI. Removed the trailing space from <i>DayOfWeek.Tuesday</i>, <i>DaysOfWeek.Tu</i> and <i>DeliveryMethod.DeliveryModePickUp</i>. <i>OpeningHoursSpecification</i>'s enum constructors now keep the enum value, so the day serializes as its URI instead of a bare name such as "Mo".</li>
<li><b>Enum members.</b> <i>DeliveryMethod.Purolator</i> (no schema.org or GoodRelations URI) now serializes as <i>https://schema.org/ParcelService</i>. <i>MedicalSpecialty.Optometic</i> and <i>Radiograpy</i> (misspelled) and <i>Dermatologic</i> (superseded by <i>Dermatology</i>) are marked <i>[Obsolete]</i>. <i>PaymentMethod.VisaCheckout</i> and <i>MusicReleaseFormatType.Acknowledgement</i> have no URI and are marked <i>[Obsolete]</i>; serializing them throws. Added members from the current schema.org vocabulary: <i>BookFormatType.AudiobookFormat</i>/<i>Pamphlet</i>, <i>EventStatusType.EventMovedOnline</i>, <i>ItemAvailability.MadeToOrder</i>/<i>Reserved</i>, <i>ReturnMethodEnumeration.KeepProduct</i>, <i>DeliveryMethod.ParcelService</i>, <i>MedicalSpecialty.Audiology</i>/<i>Dermatology</i>/<i>Ophthalmology</i>/<i>Optometric</i>.</li>
<li><b>@context.</b> Written on the root node only; nested nodes (offers, brand, rating, ...) no longer repeat it. A <i>Context</i> set explicitly on a nested node is still written.</li>
<li><b>ToJson()</b> and <b>ToIndentedJson()</b> are now virtual.</li>
<li><b>Dates.</b> Properties whose schema.org range is <i>Date</i> only serialize as <i>yyyy-MM-dd</i> via the new <i>DateOnlyConverter</i>: <i>Offer.PriceValidUntil</i>, <i>Person.BirthDate</i>/<i>DeathDate</i>, <i>Organization.FoundingDate</i>/<i>DissolutionDate</i>, <i>CreativeWork.SdDatePublished</i>, <i>WebPage.LastReviewed</i>, <i>Permit.ValidUntil</i>, <i>Vehicle.DateVehicleFirstRegistered</i>/<i>VehicleModelDate</i>/<i>ModelDate</i>.</li>
<li><b>Tire and Wheel.</b> Removed the hardcoded <i>sameAs</i> links (Wikipedia and 1010tires.com) from both constructors. <i>Wheel</i> now serializes as <i>@type Product</i> instead of the invalid <i>Product/Wheel</i>. <i>Tire</i> has typed specifications (<i>SpeedRating</i>, <i>LoadIndex</i>, <i>TreadWidth</i>, <i>Profile</i>, <i>RimDiameter</i>, <i>UTQG</i>, <i>PlyRating</i>, <i>RunFlat</i>, ...) that serialize into <i>additionalProperty</i> as <i>PropertyValue</i> entries after any values set on <i>AdditionalProperty</i>.</li>
<li><b>Other.</b> <i>MerchantReturnPolicy.AdditionalProperty</i> accepts a list of <i>PropertyValue</i> as well as a single one. <i>PropertyValue</i> has a parameterless constructor for object initializers. <i>Vehicle.SteeringPosition</i> was typed <i>DateTime?</i>; it is now the new <i>SteeringPositionValue</i> enumeration. <i>Flight.EstimatedFlightDuration</i> was typed <i>DateTime?</i>; it now accepts <i>Duration</i> or Text. <i>TrackAction.DeliveryMethod</i> had no access modifier and was never serialized; it is now public.</li>
</ul>
Added <i>Tests/JsonLdOutputTests.cs</i> with JSON comparison tests for all of the above, including a check that every freshly constructed <i>Thing</i> writes nothing but <i>@context</i> and <i>@type</i>, and that every enumeration member has a well-formed URI.

##Release v. 1.0.4.8
<i>Thing.SubjectOf</i> validator now accepts <i>Event</i> in addition to <i>CreativeWork</i>, matching schema.org's <i>CreativeWork | Event</i> union. Fixed <i>IBook.Isbn</i>/<i>Audiobook.Isbn</i> type mismatch (now <i>string</i>, matching <i>Book.Isbn</i>). Added <i>Thing.Owner</i> (<i>Organization</i> or <i>Person</i>), matching schema.org. Added <i>Action.ActionProcess</i> (<i>HowTo</i>) and <i>Action.Provider</i> (<i>Organization</i> or <i>Person</i>); <i>Action.Location</i> now also accepts Text and <i>VirtualLocation</i>. <i>CreativeWork</i> now models 47 additional schema.org properties (<i>abstract</i>, <i>accessMode</i>, <i>funder</i>, <i>funding</i>, <i>isAccessibleForFree</i>, <i>isBasedOn</i>, <i>size</i>, <i>spatial</i>, <i>thumbnail</i>, <i>wordCount</i>, and more); added new <i>Grant</i> and <i>InteractionCounter</i> types. <i>Organization</i> now models 35 additional schema.org properties (<i>acceptedPaymentMethod</i>, <i>areaServed</i>, <i>hasCertification</i>, <i>hasCredential</i>, <i>hasMemberProgram</i>, <i>knowsAbout</i>, <i>numberOfEmployees</i>, <i>parentOrganization</i>, <i>sponsor</i>, and more); added new <i>Certification</i>, <i>Credential</i>, <i>MemberProgram</i>, and <i>ShippingService</i> types. <i>Place</i> now models 25 additional schema.org properties (<i>amenityFeature</i>, <i>containedInPlace</i>, <i>containsPlace</i>, the <i>geoContains</i>/<i>geoWithin</i>/etc. topology relations, <i>hasCertification</i>, <i>latitude</i>, <i>longitude</i>, <i>maximumAttendeeCapacity</i>, <i>slogan</i>, <i>smokingAllowed</i>, <i>tourBookingPage</i>, and more). <i>Product</i> now models 26 additional schema.org properties (<i>asin</i>, <i>colorSwatch</i>, <i>countryOfOrigin</i>, <i>funding</i>, <i>gtin</i>, <i>hasCertification</i>, <i>isFamilyFriendly</i>, <i>isVariantOf</i>, <i>keywords</i>, <i>material</i>, <i>size</i>, <i>slogan</i>, and more). Removed 9 redundant property overrides now inherited from the base classes above (<i>MediaObject.EncodingFormat</i>/<i>InterpretedAsClaim</i>, <i>Article.WordCount</i>, <i>EducationalOrganization.Alumni</i>, <i>VideoObject.Thumbnail</i>, <i>ImageObject.Thumbnail</i>, <i>Episode.IsAccessibleForFree</i>, <i>TVSeason</i>/<i>TVSeries.CountryOfOrigin</i>). <i>Offer</i> now models 14 additional schema.org properties (<i>additionalProperty</i>, <i>aggregateRating</i>, <i>areaServed</i>, <i>gtin</i>, <i>hasMeasurement</i>, <i>isFamilyFriendly</i>, <i>leaseLength</i>, <i>offeredBy</i>, <i>validForMemberTier</i>, and more). <i>Person</i> now models 14 additional schema.org properties (<i>agentInteractionStatistic</i>, <i>callSign</i>, <i>children</i>, <i>funding</i>, <i>hasCertification</i>, <i>hasCredential</i>, <i>hasOccupation</i>, <i>interactionStatistic</i>, <i>knowsAbout</i>, <i>knowsLanguage</i>, <i>lifeEvent</i>, <i>pronouns</i>, <i>publishingPrinciples</i>, <i>skills</i>); added new <i>Occupation</i> type. Fixed <i>Person.Address</i> (was incorrectly typed <i>Organization</i>, now <i>PostalAddress</i>). Fixed two copy-paste bugs where <i>Person.Height</i>'s getter returned <i>WorkLocation</i> and <i>Person.Sponsor</i>'s getter/setter read/wrote <i>HomeLocation</i> instead of their own backing fields. Closed remaining schema.org property gaps across the rest of the library (<i>JobPosting</i>, <i>Accommodation</i>, <i>MedicalEntity</i>, <i>BroadcastService</i>, <i>Review</i>, <i>MusicGroup</i>, <i>LoanOrCredit</i>, <i>Event</i>, <i>Course</i>, <i>Certification</i>, and more) found by the same systematic diff. Fixed three real <i>Vehicle</i> bugs: <i>NumberOfAirbags</i> and <i>VehicleSeatingCapacity</i> serialized under wrong-cased/legacy JSON keys, and <i>VehicleIdentificationNumber</i> serialized under the wrong key entirely ("VehicleEngine", a copy-paste error) - all now serialize correctly. Continued closing gaps in <i>NewsArticle</i>, <i>MedicalTest</i>, <i>TVSeries</i>, <i>SoftwareApplication</i>, <i>PaymentCard</i>, <i>MemberProgramTier</i>, <i>EngineSpecification</i>, <i>Diet</i>, <i>Demand</i>, and <i>ApartmentComplex</i>. Continued closing gaps in <i>UnitPriceSpecification</i>, <i>Rating</i>, <i>OfferShippingDetails</i>, <i>Occupation</i>, <i>MedicalOrganization</i>, <i>MediaObject</i>, <i>GeoShape</i>, <i>GeoCoordinates</i>, <i>EducationEvent</i>, <i>CourseInstance</i>, <i>WebPageElement</i>, <i>VisualArtwork</i>, <i>TVSeason</i>, <i>SportsEvent</i>, <i>SingleFamilyResidence</i>, <i>Residence</i>, <i>Question</i>, <i>ProgramMembership</i>, <i>Physician</i>, <i>MerchantReturnPolicy</i>, <i>InteractionCounter</i>, <i>Credential</i>, <i>BuyAction</i>, <i>Blog</i>, <i>AudioObject</i>, and <i>Article</i>. Fixed four more real bugs found along the way: <i>CourseInstance.CourseMode</i> serialized under the wrong key ("coursePrerequisites"); <i>OrderItem</i> had three different properties (<i>OrderItemNumber</i>, <i>OrderItemStatus</i>, <i>OrderQuantity</i>) all serializing under the same "orderItemNumber" key; <i>Blog.BlogPost</i> was missing its <i>JsonProperty</i> attribute entirely; and <i>Order</i>/<i>OrderItem</i>'s <i>OrderStatus</i> enum serialized as a number instead of its name. Also upgraded <i>MedicalOrganization.MedicalSpecialty</i> from <i>string</i> to the proper <i>MedicalSpecialty</i> enum (matching <i>MedicalClinic</i>'s existing pattern), removing the need for duplicate overrides in <i>MedicalClinic</i>, and removed 5 more redundant property overrides (<i>Apartment</i>/<i>HotelRoom</i>/<i>Suite.Occupancy</i>, <i>HotelRoom</i>/<i>Suite.Bed</i>) now inherited from <i>Accommodation</i>. Finished the audit by closing the remaining single-property gaps across roughly 40 more classes (<i>WinAction</i>, <i>WebSite</i>, <i>WebPage</i>, <i>VideoObject</i>, <i>TypeAndQuantityNode</i>, <i>TravelAction</i>, <i>TradeAction</i>, <i>SportsTeam</i>, <i>ShippingService</i>, <i>Service</i>, <i>SellAction</i>, <i>Schedule</i>, <i>QuantitativeValue</i>, <i>PropertyValue</i>, <i>PriceSpecification</i>, <i>PostalAddress</i>, <i>MenuItem</i>, <i>LodgingBusiness</i>, <i>LocalBusiness</i>, <i>ItemList</i>, <i>InformAction</i>, <i>ImageObject</i>, <i>HowTo</i>, <i>Hospital</i>, <i>FinancialService</i>, <i>CreativeWorkSeries</i>, <i>ContactPoint</i>, <i>ConsumeAction</i>, <i>CompoundPriceSpecification</i>, <i>Comment</i>, <i>Collection</i>, <i>Brand</i>, <i>Book</i>, <i>Audiobook</i>, and <i>Answer</i>), and confirming the remaining "missing" items across the codebase are all legacy names already superseded by implemented properties (e.g. <i>Organization.awards/contactPoints/members/serviceArea</i>, <i>CreativeWork.awards/encodings/fileFormat</i>, the <i>TVSeries</i>/<i>RadioSeries</i>/<i>VideoGameSeries.episodes/season/seasons</i> family) or intentionally untouched (the obsolete root <i>EntryPoint</i>, superseded by <i>Intangible.EntryPoint</i>). Fixed five more real bugs: <i>ChooseAction.Option</i> serialized under "option" instead of "actionOption"; <i>BedDetails.typeOfBed</i> shared its <i>JsonProperty</i> key with <i>NumberOfBeds</i>; <i>Audience</i>'s geographic area serialized under "administrativeArea", which was never a valid schema.org property name (the correct name is <i>geographicArea</i>); <i>NutritionInformation.SugarContent</i> serialized under "occupancy"; and <i>TravelAction.Distance</i> had no access modifier and no <i>JsonProperty</i> attribute, making it completely inert. This completes the systematic schema.org audit: every class in the library matching a current schema.org type now implements all of that type's non-superseded properties. <i>Person</i>/<i>Organization</i>/<i>Place.Address</i> (and <i>IPlace.Address</i>/<i>Addresses</i>) now accept Text in addition to <i>PostalAddress</i>, matching schema.org's documented union; <i>Organization</i>/<i>Place.Addresses</i> is now <i>List&lt;object&gt;</i> instead of <i>List&lt;PostalAddress&gt;</i> to support this.
